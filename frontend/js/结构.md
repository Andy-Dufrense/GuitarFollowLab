# 前端结构（产品页）

> 2026-09-28 立。**加新模块、改现有模块，都按这份来。**
> 背景：`follow-score.js` 一度长到 2700 行，其中一个 `micTickBody()` 就 1460 行、
> 摸到模块里 71 个变量 —— 一个赋值写错（`lastOnsetMs` 和 `onsetAtMs` 被赋成同一个值）
> 就让"抢拍/拖拍"几个月没生效，谁都没看出来。这份规矩就是为了不再发生第二次。

---

## 1. 一句话规矩

**入口只做装配；能力一层层往下靠；谁都不许反过来 import。**

```
product.js          入口：建状态、建各层、挂事件          ← 目标 ~150 行
   ↓ 只能往下
app/                页面能力（状态 / 光标 / 跟节拍 / 诊断 / 和弦 / 音格 / 会话日志）
   ↓ 只能往下
engine/             信号与判定（薄壳 → backend/engine/，产品页与作业检查共用同一份）
```

同层之间**不许互相 import**（`app/` 里的纯工具例外，比如 `cursor.js` 那种纯函数）。

---

## 2. 一个文件长什么样

**工厂 + 依赖注入**，没有例外：

```js
// app/xxx.js
export function createXxx({ $, setVerdict, getNotes, setNoteIdx }) {
  let own = null;                    // 只属于自己、别人不该碰的可变状态

  function doThing() { ... }

  return {
    doThing,
    get own() { return own; },       // 外面真要读，就给语义化的 getter
  };
}
```

三条硬要求：

1. **依赖全部从参数进来**；模块内部不读全局变量、不直接 `document.getElementById`（用注入的 `$`）。
2. **自己独占的状态留在闭包里**；共享状态用 `get/set` 注入 ——
   例：`beat`（第几拍）被「和弦卡」和「alphaTab 光标」共用，所以它留在宿主，两边都通过 get/set 读写，
   **绝不各存一份**（存两份就会出现"卡片第 2 拍、光标在第 3 拍"）。
3. 导出**语义化方法**（`resetRun()`、`markWrong(idx)`、`lastOnset()`），
   不要导出 `getState()/setState()` 这种把内部结构摊开的东西。

## 4. `follow-score.js` 的施工图（按顺序做，每步都要过 §6 的门）

| # | 拆什么 | 目标文件 | 量 | 风险 |
|---|---|---|---|---|
| 1 | 会话状态（`noteIdx / userPickedStart / holdUntilMs / countinPeaks / wrong* / good / bad / missed / unclearCount / earlyCount / lateCount / timingDevs / firstJudgeMs / lastJudgeMs …`） | `app/session-state.js` | ~40 个变量 | 中 |
| 2 | alphaTab 渲染 + 光标（`initAlphaTab / buildTickMap / showAlignLine / markNote / highlightCurrent / fillTracks / applyTrack`） | `app/score-view.js` | ~300 行 | 中 |
| 3 | 音格子 + 节拍器（`renderCells / highlightCell / countIn / metro`） | `app/arp-cells.js` | ~100 行 | **高**（试过两次，都碰坏 6 条时间断言；先做诊断） |
| 4 | `micTickBody` 分段（起音 / 读数 / 判定 / 结论） | `app/judge-loop.js` + 各段 | ~1460 行 | **高**（判定心脏） |
| 5 | 入口 | `product.js`（**别叫 main.js**，那名字是老页面的，已删） | ~150 行 | 低 |

顺序为什么是这个：**先状态、再被动块、最后主动块**。
实测规律：只在按钮/切曲目时被调用的"被动块"（和弦练习）一次就搬成了；
在麦克风循环里的"主动块"（音格子 + 节拍器）两次都崩。

## 5. 判定那三件事不许碰

起音 / 读数 / 判定（`backend/engine/`）**只能调用，不能重写、不能就地调参**：
那是跟弹"能力的家"，作业检查（HomeworkGrader）也在 import 同一份。要动它，
先做离线验证并给出「真音没丢、杂音没进」两边数字。这条是铁律，写在 `AGENTS.md` 里。

## 6. 每改一次前端，跑这四道门

```bat
node test\gt-notes.mjs            :: 真机 39 拨弦，必须 39/39
node test\test-follow-page.mjs    :: 产品页判定回归，必须「全部通过」
node test\test-product-page.mjs   :: 产品页加载/自检，必须「全部通过」
node test\check-build.mjs         :: 版本号三处一致
```

再加两条：

- **改了前端 JS 必须抬版本号**：`node vc_gf/bump-build.mjs 0928-HHMM`，否则手机吃缓存，
  你在手机上测的还是旧代码。
- 手上有真机录音时，跑一次端到端：`VC_TIMELINE=<时间轴> node test/test-follow-real.mjs <录音.f32>`，
  拿一个**已知答案**（例：6415 那条是对 30 / 错 3）对比，比"测试全过"更能说明判定没被碰。

## 7. 加新功能时的检查单

1. **先定位到哪一层**：状态（`session-state`）/ 能力（`app/`）/ 视图（`app/`）/ 入口（`product.js`）。
   拿不准就问一句："它自己独占什么？它需要别人给什么？"
2. **一个文件一件事**，文件名一句话说清它管什么（`chord-practice`、`session-log` 这种）。
3. 写成 `createXxx({ 依赖 })`，依赖注入，**不碰模块外的变量**。
4. 需要跨模块共享的状态 → 进 `session-state`（唯一真相），别各存一份。
5. 只有 `product.js` 能绑 DOM 事件、建 alphaTab 实例；`app/` 里的模块只做自己那件事。
6. 跑 §6 那四道门 +（有条件时）真机端到端。
7. 提交信息里写清"搬了什么、验证结果"，方便回溯 ——
   今天那个 `devMs` 的 bug 就是靠"真机 55 个音 devMs 非空 0 个"这种数字定位的。
